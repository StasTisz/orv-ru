## 1. Жёсткие инварианты и правила безопасности

1. **Никогда не редактируй сгенерированный HTML/EPUB вручную** в `output/` — любые правки вносятся только через пайплайн и исходные переводы в `data/chapters/cont/`.
2. **Не изменяй папку `../reference-orv-reader/`** — это эталонный read-only источник глав и изображений.
3. **Работай через Protected Payload (`export-packet` → `import-translation`), а не вручную с `.txt`-тегами.** Инструмент сам защищает `<cover>`, `<img>`, `***`, переносы `<br>`, число строк в окнах `+`/`++` и термины глоссария.
4. **Не делай `git commit`, `git merge` или `git push` без прямой команды пользователя.**
5. **Никогда не коммить папки `data/`, `output/`, `site/`, `*.epub`, `.env`** — в Git живёт только чистый код движка, шаблоны, тесты, документация и глоссарий.

## 2. Пошаговый цикл автономного перевода главы

### Шаг 1. Получить следующую непереведённую главу
```bash
python3 scripts/next_packet.py
# или явно:
PYTHONPATH=src python3 -m orv_ru export-packet 553 --output data/work/packet_553.json
```
Скрипт создаст `data/work/packet_<N>.json`, содержащий:
- `title` и `items` (`block_index`, `kind`, `lines`, `expected_br_counts`);
- `rules` — правила стиля;
- `glossary` — только те термины из `glossary/orv_glossary.toml`, которые реально встречаются в этой главе.

### Шаг 2. Перевести пакет в JSON
Создай файл `data/work/translated_<N>.json` строго в формате:
```json
{
  "chapter_number": 553,
  "title": "<переведённый заголовок>",
  "items": [
    {
      "block_index": 1,
      "lines": ["<переведённая строка>"]
    }
  ]
}
```
Обязательно проверь перед импортом:
- каждый `block_index` из `packet_<N>.json` присутствует ровно 1 раз;
- длина массива `lines` каждого элемента совпадает с исходной;
- количество тегов `<br>` в каждой строке совпадает с `expected_br_counts`.

### Шаг 3. Импортировать с автоматической проверкой
```bash
PYTHONPATH=src python3 -m orv_ru import-translation <N> data/work/translated_<N>.json --strict-glossary --json
```
- Если код возврата **`0`**: глава прошла все структурные и терминологические проверки и автоматически сохранена в `data/chapters/cont/<N>.txt`.
- Если код возврата **`1`**: файл на диск **не записан**. Прочитай поля `structural_validation.issues` и `glossary_validation.issues` в JSON-выводе, исправь `data/work/translated_<N>.json` и повтори импорт.

### Шаг 4. Собрать и проверить сайт + EPUB
```bash
python3 scripts/verify_and_build.py --json
```
Скрипт прогоняет `validate`, `check-glossary`, собирает `output/epub/orv_cont_ru.epub` и обновляет статический сайт `output/site/`.

## 3. Стандарты литературного перевода на русский язык

- **Язык и стиль:** живой, естественный русский язык художественной прозы. Избегай канцелярита и дословных английских калек (*«сделал шаг вперёд»*, *«уголки его губ поползли вверх»* в каждом абзаце).
- **Диалоги:** оформляй по-русски (`— Реплика.`, или сохраняй `«...»` / `「...」`, если это цитата или внутренний голос в блоке `quote`).
- **Корейские гоноративы:** сохраняй `-сси`, `-ним`, `аджосси`, `хён`, `онни`, `нуна`, `оппа` там, где они передают дистанцию и характер отношений (например, `Писатель-ним`, `Читатель-ним`).
- **Эмоции и грубость:** не смягчай ругательства и резкие реплики персонажей.
- **Склонение корейских имён:** мужские имена склоняются естественно (`Ким Докча → Ким Докчи`, `Ю Джунхёк → Ю Джунхёка`, `Ли Хакхён → Ли Хакхёна`); женские имена на согласный не склоняются (`Хан Суён`, `Чон Хивон`, `Син Юсон`, `Ли Джихё`, `Кён Сэин`).
- **Ловушки лора (проверять всегда):**
  - `Secretive Plotter` (`Скрытный Интриган`) ≠ `Sneaky Schemer` (`Коварный Интриган`);
  - `Oldest Dream` = строго `Древнейшая Мечта`;
  - `Probability` = строго `Вероятность`;
  - `Dokkaebi` = строго `Токкэби`;
  - `Unrealized Thought` = строго `Невоплощённая Мысль` (ед. ч.);
  - Чан Хаён: от посторонних — мужской род, от себя и близких — женский;
  - Ю Джунхёк 41-й регрессии сражается большим копьём (`Копьё Тёмной Небесной Луны`), не мечом.

## 4. Правила изменения кода движка

- Соблюдай слои из [`ARCHITECTURE.md`](ARCHITECTURE.md): модуль `domain/` не должен импортировать `parsing/`, `storage/`, `rendering/`, `translation/` или `config.py`.
- После любых правок кода обязательно запускай `pytest` (или `python3 scripts/verify_and_build.py --with-tests`).
